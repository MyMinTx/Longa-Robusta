## 1. ค่าที่ใส่ใน LIFF app (A4 ในเอกสารเดิม)

| ช่อง | ใส่ | หมายเหตุ |
|---|---|---|
| Endpoint URL | `https://longa-robusta.vercel.app` | ไม่ต้องมี path หรือ `?…` ต่อท้าย |
| Size | **Full** | |
| Scopes | `openid` **(ต้องมี)** · `profile` | ไม่มี `openid` → `liff.getIDToken()` ได้ null → backend ตอบ 401 ทุกครั้ง |
| Add friend option (Bot link) | **On** (Normal หรือ Aggressive) ผูกกับ OA | Push ส่งถึงเฉพาะคนที่เป็นเพื่อน OA |
| Scan QR / อื่น ๆ | ปิดได้ | แอปไม่ได้ใช้ |

**สำคัญ:** channel ที่มี LIFF กับ Messaging API ต้องอยู่ **Provider เดียวกัน** — backend ใช้ `sub` จาก ID token ของ LIFF เป็นปลายทาง Push ถ้าคนละ Provider userId ไม่ตรงกัน Push จะไม่ถึง

### ส่งค่าให้ใคร
| ค่า | ให้ | ทาง |
|---|---|---|
| LIFF ID (`2000000000-xxxxxxxx`) | มิ้น (`web/config.js`) และธร (`.env` → `LIFF_ID`) | แชตกลุ่มได้ |
| Channel ID ของ channel ที่มี LIFF | ธร (`.env` → `LIFF_CHANNEL_ID`) | แชตกลุ่มได้ |
| Channel access token (Messaging API) | ธรเท่านั้น | **แชตส่วนตัว** |

**ให้ธรกับมิ้นเปิดพร้อมกัน** — ถ้าคนหนึ่งใส่แล้วอีกคนยังไม่ใส่ แอปจะใช้ไม่ได้หรือทุกคนเห็นล็อตเดียวกัน (ตารางใน `01_for_backend.md` ข้อ 3)

### Testers
Roles → เพิ่ม มิ้น · ธร · กาฟิว · **มือถือเดโม** เป็น Tester (ตอน channel ยัง Developing คนอื่นเปิดไม่ได้) · ก่อนนำเสนอเปลี่ยนเป็น Published (C2 เดิม)

## 2. ลิงก์ที่ใช้

| ลิงก์ | ใช้ทำอะไร |
|---|---|
| `https://liff.line.me/<LIFF_ID>` | เปิดแอป (Rich menu / QR) |
| `https://liff.line.me/<LIFF_ID>?lot=LOT-T49-1` | ปุ่มใน Push (backend สร้างให้เองเมื่อตั้ง `LIFF_ID`) |
| `https://liff.line.me/<LIFF_ID>?demo=1` | มือถือเดโม: มีแถบปุ่ม รีเซ็ต / เร่งเวลา / ปกติ ล่างจอ |
| `https://longa-robusta.vercel.app/?mock=ready` | ดูหน้าจอโดยไม่ต้องมี backend (ทางสำรอง ดูข้อ 5) |

ส่งลิงก์นี้ในแชต LINE แล้วกดจากในแชต จะเปิดในแอป LINE (ได้ตัวตนจาก LIFF) · เปิดจากเบราว์เซอร์อื่นจะพาไปล็อกอิน LINE ก่อน

### ตั้งมือถือเดโมครั้งแรก
1. เปิด `https://liff.line.me/<LIFF_ID>?demo=1` จากแชต LINE ในมือถือเดโม
2. กดปุ่ม "เร่งเวลา" ครั้งแรก → ช่องให้ใส่ **X-Demo-Key** (ขอจากธรทางแชตส่วนตัว) → มือถือจำไว้ ครั้งต่อไปไม่ถาม
3. ถ้าใส่ผิด แอปขึ้น "ต้องใส่ X-Demo-Key" แล้วลืมค่าเดิม กดใหม่จะถามอีกครั้ง
4. **อย่า**ส่งลิงก์ `?demokey=…` ในกลุ่มหรือใส่ในสไลด์/QR

## 3. Push ↔ หน้าในแอป (ให้การ์ดกับหน้าจอพูดเรื่องเดียวกัน)

| Push | ปุ่มในการ์ดพาไป | หน้าแอปแสดง |
|---|---|---|
| พร้อมขาย | หน้า 03 พร้อมขาย | ราคาประเมิน 48pt (ทศนิยม 1 ตำแหน่ง เช่น 114.2) · "ระบบจะไม่ขายต่ำกว่า 91.4 บาท/กก." · ความชื้น ✓ · เมล็ดเสีย + "เกรด 2" |
| ต้องดูแล | หน้า 09 | หัวข้อ = `alert.message` · เมล็ดเสียตัวแดง หรือความชื้นตัวแดง · ปุ่ม "ขอตรวจใหม่" |
| ขายได้แล้ว | หน้า 08 | "ขายครบ 4 กระสอบ" · ราคา(เฉลี่ย)ที่ได้ · "สูงกว่าราคาต่ำสุด X บ./กก. (+Y%)" |

ให้การ์ดใช้คำ/รูปแบบเดียวกับแอป:
- ชื่อเกรดภาษาไทย (`GRADE_2` → "เกรด 2") — ตอนนี้ `push.py` ยังโชว์ `GRADE_2` (ธรมีโค้ดแก้ใน `01` ข้อ 6)
- ตัวเลขราคา 1 ตำแหน่ง · หน่วย "บ./กก." · สีหลัก `#00813F` · สีสถานะ: พร้อมขาย `#006B34` / ต้องดูแล `#B3261E` / ขายแล้ว `#5A3A26`
- ภาพ hero ในการ์ด = `vis_url` ซึ่งต้องเป็น https (ธรต้องตั้ง `PUBLIC_BASE_URL` เป็น URL tunnel) และไม่มีภาพก็ต้องดูดี
- ปุ่มในการ์ดปุ่มเดียว ข้อความสั้น (ตอนนี้: "ดูรายละเอียด" / "ดูวิธีแก้" / "ดูสรุปการขาย")

ดู Flex JSON ที่ backend สร้างจริง: `curl $API/debug/pushes -H "X-Demo-Key: <DEMO_KEY>"` → วางใน Flex Message Simulator

## 4. สคริปต์เดโม 3 นาที (ฉบับกดปุ่มจริงในแอป)

ปรับจาก C3 เดิมให้ตรงกับปุ่มที่มีจริง · เตรียมก่อนขึ้นเวที: มือถือเดโมเปิด `…?demo=1` ค้างไว้, กด **รีเซ็ต** แล้ว (ล็อตใหม่ความชื้น ~18%)

| เวลา | คนกดมือถือทำ | จอแสดง | คนพูด (สรุป) |
|---|---|---|---|
| 0:00 | — | สไลด์ปัญหา | เกษตรกรไม่รู้ว่าตากพอหรือยัง ขายได้เท่าไหร่ ไม่ไว้ใจราคาที่ไม่มีเหตุผล |
| 0:20 | เปิดแอป | หน้า 02 กำลังตาก · ความชื้น ~18% · ป้าย "ข้อมูลจำลอง" มุมขวาบน | ความชื้นมาจาก Track 1 · ตอนนี้เป็นข้อมูลจำลอง (ชี้ป้าย) |
| 0:40 | แถบเดโม → **เร่งเวลา** | ตัวเลขความชื้นลดลงเรื่อย ๆ (แอปดึงใหม่ทุก 10 วิ) | แห้งถึงเกณฑ์แล้วระบบตรวจเมล็ด (Track 2) และแจ้งเตือนเอง |
| ~1:10 | รอ Push เด้ง → กดปุ่มในการ์ด | หน้า 03 พร้อมขาย | เปิดจาก LINE ได้ทันที ไม่ต้องติดตั้งแอป |
| 1:20 | กด "ราคานี้มาจากไหน" | sheet 04 ตารางสูตร | ราคามาจากสูตรตลาด โปร่งใสทุกบรรทัด ไม่ขายต่ำกว่า 80% |
| 1:40 | "เข้าใจแล้ว" → "ยืนยันขาย" → "ยืนยันขาย" | sheet 06 → หน้า 07 กำลังขาย | เกษตรกรตัดสินใจครั้งเดียว Agent (Track 3) ขายแทน |
| 2:00 | รอ (หน้า 07 ดึงทุก 5 วิ) | แถบกระสอบเต็มทีละช่อง · รายการ "ขายได้" | ระบบบอกทุกขั้นที่ทำ ไม่ขายต่ำกว่าราคาต่ำสุด |
| ~2:20 | Push "ขายได้แล้ว" → กดเปิด | หน้า 08 ขายแล้ว | ได้ราคาเท่าไหร่ สูงกว่าราคาต่ำสุดกี่ % |
| 2:40 | — | สไลด์สรุป | ESP32 + AI + Agent + LINE = แพลตฟอร์มเดียว · เปลี่ยนเป็นข้อมูลจริงได้โดยไม่แก้แอป |

หลังจบ: กด **ปกติ** ในแถบเดโม (คืนความเร็ว) แล้ว **รีเซ็ต** เตรียมรอบต่อไป
เวลารอจริงขึ้นกับ Pi: ตาม `04_ธร_Backend.md` เร่งแล้วพร้อมขาย ~40 วิ · ขายครบ ~20–40 วิ — ซ้อมจับเวลาจริง 3 รอบ

ถ้าอยากโชว์หน้า "ต้องดูแล": ในตัวจำลอง ผลตรวจสุ่มเกรด (20% เป็น poor → เสีย > 7%) จึงอาจเจอเองระหว่างเดโม — ให้ใช้เป็นจุดเล่า: กด "ขอตรวจใหม่" (ในโหมดเดโมจะจำลองว่าคัดเมล็ดแล้ว ผลจะดีขึ้น) → กลับเป็นพร้อมขาย

### คำถามกรรมการเพิ่มเติม (นอกจาก C3 เดิม)
- **"ถ้าข้อมูลค้าง/เน็ตหลุดจะเกิดอะไร"** → เปิด `https://longa-robusta.vercel.app/?mock=stale` ให้ดู: แถบแดง "ข้อมูลไม่อัปเดตมา 2 ชั่วโมง" และปุ่มขายกดไม่ได้
- **"กดขายซ้ำจะขายซ้ำไหม"** → ปุ่มส่งได้ทีละครั้ง และ backend รับกดซ้ำได้ผลเดิม
- **"ราคาต่ำสุดมาจากไหน"** → sheet 04 กล่องเขียว 80%

## 5. ทางสำรองถ้า backend / LINE มีปัญหาตอนเดโม

| ปัญหา | ทางสำรอง |
|---|---|
| Push ไม่เด้ง | เปิดแอปจาก Rich menu / ลิงก์ในแชตเอง แอปดึงข้อมูลใหม่ทุก 10 วิอยู่แล้ว |
| Pi ดับ / tunnel หลุด | เปิดในเบราว์เซอร์มือถือ: `https://longa-robusta.vercel.app/?mock=drying` → `?mock=ready` → กดยืนยันขาย (สลับเป็นหน้ากำลังขายเอง) → `?mock=sold` · ไม่ต้องมี backend แต่ต้องมีเน็ต |
| ไม่มีเน็ตเลย | วิดีโอสำรอง (C4 เดิม) |

ลิงก์ mock ทั้งหมด: `drying` `drying-priced` `ready` `ready-counts` `selling` `selling-offers` `sold` `alert` `alert-moisture` `stale`
